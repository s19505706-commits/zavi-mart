# Phase 1 Safe Audit Report

Read-only audit of `app/`, `components/`, `lib/`, `public/`, and `app/api/`.
No application code or data files were changed.

## A) WHAT IS WORKING - Must Be Preserved

- **TypeScript and imports:** `npm run typecheck:next` (`tsc --noEmit`) completed successfully. No TypeScript errors were reported in admin pages, storefront pages, API routes, or their imported TypeScript modules. The IDE selection `ngify(products, null, ...)` is part of `JSON.stringify(products, null, 2)` in [`lib/local-markaz-products.ts`](./lib/local-markaz-products.ts), not a misspelled identifier.
- **Storefront:** The home page loads departments, products, flash deals, hot deals, new arrivals, and shipping settings. Department/category listings, product details, deal details, search, a local-storage cart, checkout form, address lookup, and customer product reviews are present. Relevant routes include [`app/page.tsx`](./app/page.tsx), [`app/department/`](./app/department), [`app/product/`](./app/product), [`app/cart/page.tsx`](./app/cart/page.tsx), and [`app/checkout/`](./app/checkout).
- **Admin panel:** Existing pages cover the dashboard and reports, products and product history/deleted products, Markaz/product imports, departments/categories, flash and hot deals, shipping/free delivery, customers, orders/supplier fulfillment, and notifications. These pages and their shared admin UI components should be preserved.
- **Shared catalog path:** Storefront and admin product views use the same `/api/products` endpoint, which merges database products, local stores, Markaz products, and mock products. Product persistence and serialization are shared through [`lib/product-catalog.ts`](./lib/product-catalog.ts), [`lib/local-products.ts`](./lib/local-products.ts), [`lib/local-markaz-products.ts`](./lib/local-markaz-products.ts), and the [`Product` model](./models/Product.ts). Admin edits and ordinary product creation use this shared API.
- **Existing backend/API functionality:** API routes exist for products, orders, checkout, departments/categories, shipping, deals, notifications, customers, comments/replies, search, product history, and admin statistics. Many admin mutations use shared API handlers and admin authorization.
- **Existing static assets:** Both PWA manifests are static files in `public/`. The customer and admin manifests reference logo icon files under `public/logos/`; these assets are present. The placeholder image referenced by the Markaz import UI is also present.

## B) WHAT IS BROKEN / MISSING - Needs Fixing

- **Vercel persistence limitation:** Local JSON stores use `.data` locally but switch to `/tmp/.data` when `VERCEL` is set. This affects local products and Markaz imports, departments/categories, orders, notifications/comments, deal data, shipping settings, and product history. `/tmp` is not durable shared storage across serverless invocations or instances, so data saved via these fallbacks can disappear or be inconsistent. A persistent database/storage service is needed for production use of fallback-backed features. Examples: [`lib/local-products.ts`](./lib/local-products.ts), [`lib/local-orders.ts`](./lib/local-orders.ts), [`lib/local-notifications.ts`](./lib/local-notifications.ts), and [`lib/department-category-store.ts`](./lib/department-category-store.ts).
- **Product write modes differ:** Ordinary product creation and updates in [`app/api/products/route.ts`](./app/api/products/route.ts) require `MONGODB_URI`; they return an error when it is not configured. Markaz import in [`app/api/products/import/route.ts`](./app/api/products/import/route.ts) instead has a local-file fallback, which is ephemeral on Vercel. Thus the admin can display merged catalog sources, but not every source supports the same durable write behavior.
- **Tracked Markaz data is disconnected from runtime reads:** The repository contains [`data/markaz-products.json`](./data/markaz-products.json), while [`lib/local-markaz-products.ts`](./lib/local-markaz-products.ts) reads and writes `.data/markaz-products.json` (or `/tmp/.data/markaz-products.json` on Vercel). The runtime code does not load the tracked `data/` file, so changes or records in that file are not automatically part of the API catalog. The separate [`lib/mock-products.ts`](./lib/mock-products.ts) catalog is hard-coded.
- **Checkout and admin order data have separate persistence paths:** [`app/api/checkout/route.ts`](./app/api/checkout/route.ts) proxies checkout to the separately configured backend URL and mirrors a successful order into the local order store. Admin order and dashboard APIs read MongoDB plus that local store. The checkout route does not directly write the MongoDB `Order` model, so the code does not establish that externally processed orders reliably appear in admin on Vercel; this depends on the external backend and local mirror being shared/persistent. Checkout also requires `NEXT_PUBLIC_API_URL` to be configured outside development.
- **Demo data can appear as real admin data:** [`lib/mock-products.ts`](./lib/mock-products.ts) supplies a hard-coded catalog; [`lib/local-orders.ts`](./lib/local-orders.ts) creates six demo orders when its local order file is absent. Configure and seed production persistence, and ensure demo records are not presented as live data.
- **Customer sign-in is only a browser-side placeholder:** [`app/login/page.tsx`](./app/login/page.tsx) accepts email/password locally, but the password is not sent to or verified by an authentication service; the email is saved through [`app/auth-context.tsx`](./app/auth-context.tsx) in local storage. Customer account authentication and server-side session management are not implemented.
- **Admin key has an unsafe built-in fallback:** [`lib/admin-session.ts`](./lib/admin-session.ts) defaults the admin credential to `zavi123` when neither admin key environment variable is configured. Admin APIs relying on `requireAdmin` can accept that fallback credential. Production configuration should fail closed rather than use a known default.
- **Professional-store gaps:** Checkout supports only cash on delivery in [`app/api/orders/route.ts`](./app/api/orders/route.ts); the storefront cart exposes a hard-coded `ZAVI10` coupon in [`app/cart/page.tsx`](./app/cart/page.tsx), with no coupon-management API found. No automated test/spec files or test script were found in the project scan; the successful TypeScript check verifies types/import resolution but does not verify end-to-end storefront, admin, checkout, persistence, or payment behavior.
- **Missing public sound file:** [`components/admin/AdminBellWithSound.tsx`](./components/admin/AdminBellWithSound.tsx) references `/sounds/notify.mp3`, but `public/sounds/` contains only `.gitkeep`. The component catches playback failure and uses a Web Audio fallback beep, so the notification cue has a fallback, but the missing file causes a failed asset request whenever playback is attempted.
- **Missing import/typo scan result:** No unresolved TypeScript imports or TypeScript errors were found. The local-Markaz `JSON.stringify` line noted above is not a typo.
